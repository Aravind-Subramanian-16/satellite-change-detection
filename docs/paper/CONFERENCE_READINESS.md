## Executive assessment

The project has a promising, focused research direction: measure how a
high-resolution-trained change detector behaves under controlled degradation,
then contrast that experiment with cross-dataset results. The responsible
publication story is a carefully bounded case study with transparent negative
results—not a claim to outperform prior work. The saved numerical evidence is
now available and summary derivation checks pass. Full independent reproduction
is still blocked by missing source imagery, model weights, some run records and
verified citations.

The application and the paper also describe different systems. The current
React/TypeScript application performs RGB difference screening, supports
uploaded-pair ROI selection and synchronized zoom, and clearly identifies
synthetic fallback imagery. It does not run the CNN, NDVI/NDBI or SCL pipeline
described in the supplied draft. The manuscript's system overview has been
corrected to state this distinction; no application accuracy is claimed.

   paper tables regenerated byte-identically. The OSCD evidence generator now
   records repository-relative source paths for local inputs. This reproduces derived
   statistics, **not** model inference or the original evaluation runs.
3. **Remaining reproduction gap:** OSCD/LEVIR-CD imagery, labels and the CNN
   checkpoint are not present. The historical test-scoring event count and
   complete runtime environment are not recorded. Raw model predictions cannot
   be independently recreated here.
4. **Publication provenance:** regenerated OSCD evidence stores a
   repository-relative source path instead of a machine-specific absolute
   volume path. The source result JSON hash is unchanged.
5. **Scientific framing:** no superiority, novelty or “resolution-independent
   alternative” claim should be made. The simulation varies blur/resampling

   sensor, geography and other domain differences.
6. **Bibliography:** nine references are now included in the LaTeX source, and

## Recommended publication positioning

Frame the contribution as a **single-model resolution-degradation case study
with a separately reported cross-dataset evaluation**. State the exact data,
preprocessing, interpolation, threshold, metric aggregation and prior test-set
use. Keep the app as implementation context only; do not present it as a
validated deployment of the evaluated model. Discuss reproducibility and
limitations as strengths of the report, not as proof of novelty or superiority.

To make the work stronger than a descriptive demo, the next scientific
improvement should be a fully reproducible evaluation package and an
independent, pre-specified validation—not unverified accuracy claims or a
post-hoc change to the old test protocol. The current checkout does not contain
the imagery and weights needed to rerun the original evaluations.
